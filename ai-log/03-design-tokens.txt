⏺ Да, Dependabot следит за обновлениями зависимостей. Это встроенный бот GitHub:
  раз в неделю он сравнивает версии в репозитории с последними опубликованными
  и сам открывает PR с обновлением. Мы подключили его на шаге 2, настройки лежат
  в .github/dependabot.yml. Он следит за двумя вещами:

  - npm-пакеты из package.json. Минорные и патч-обновления приходят одним общим
    PR в неделю. Мажорные приходят отдельными PR, открытых одновременно не
    больше трёх.
  - GitHub Actions — готовые шаги, из которых собран CI в
    .github/workflows/ci.yml. Все обновления приходят одним PR.

  Зачем это нужно:
  - Безопасность. Если в пакете найдут уязвимость, Dependabot сам предложит
    исправленную версию.
  - Устаревание. Старые версии actions со временем перестают поддерживаться:
    GitHub, например, переводит их на новый Node.js, и старые начинают выдавать
    предупреждения, а потом ломаются.
  - Проверка на CI. На каждом таком PR запускается наш CI, и сразу видно, ломает
    ли что-то обновление.

  PR #3 обновляет версии трёх actions в ci.yml, код сайта он не трогает:

  ┌──────────────────────────────────────────────┬──────┬───────┐
  │                    Action                    │ Было │ Стало │
  ├──────────────────────────────────────────────┼──────┼───────┤
  │ actions/checkout (скачивает код репозитория) │ v4   │ v7    │
  ├──────────────────────────────────────────────┼──────┼───────┤
  │ pnpm/action-setup (ставит pnpm)              │ v4   │ v6    │
  ├──────────────────────────────────────────────┼──────┼───────┤
  │ actions/setup-node (ставит Node.js и кэш)    │ v4   │ v7    │
  └──────────────────────────────────────────────┴──────┴───────┘

  Все три обновления мажорные, но CI на этом PR уже прошёл с новыми версиями, и
  проверка «Lint, typecheck, test, build» зелёная. Значит, они у нас работают. С
  PR #4 он не пересекается, потому что меняет только ci.yml. Его можно спокойно
  мержить.

  Одна оговорка на будущее. Мажорные обновления npm-пакетов (например, next 16 →
  17 или zod 4 → 5) придут отдельными PR, и до дедлайна 19.10 я бы их не
  мержил: даже при зелёном CI они могут незаметно поменять поведение. Если
  хочешь, добавлю в dependabot.yml правило игнорировать мажорные версии npm до
  сдачи.
