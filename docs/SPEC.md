# «Кварта» – ТЗ на разработку лендинга

14.10.2026 · Andrei

Одностраничный лендинг на Next.js с формой заявки, эндпоинтом `POST /api/lead` и хранением в Postgres. Деплой на Vercel, сдача до 19.10.2026 18:00 по Москве. Документ – задание для Claude Code и чек-лист для нас.

## 2. Стек и ключевые решения

Страница собирается статически (SSG), клиентский JS только у формы, атрибуции и анимаций. Новые зависимости сверх таблицы – только после согласования.

| Слой | Выбор | Почему |
| --- | --- | --- |
| Фреймворк | Next.js 16 (App Router), React 19, TypeScript strict | Основной стек работодателя; RSC дают минимум JS. Версия – актуальная стабильная из `create-next-app@latest` |
| Пакетный менеджер | pnpm | Быстрая установка в CI и на Vercel |
| Стили | Tailwind CSS v4, токены макета в `@theme` | Ноль runtime, токены в одном месте |
| Шрифты | `next/font/google`: Oswald, Onest, JetBrains Mono, subsets latin + cyrillic, `display: swap` | Самохостинг, нет запросов к Google, нет сдвига вёрстки |
| Картинки | `next/image`, AVIF/WebP, `sizes` на каждом фото | Корректный размер под телефон |
| Валидация | zod, одна схема в `lib/lead/schema.ts` для клиента и сервера | Одинаковые правила и тексты ошибок |
| Телефон | Своя функция `normalizeByPhone()` без libphonenumber | Только 4 мобильных кода – библиотека на \~80 КБ не окупается |
| Эндпоинт | Route Handler `app/api/lead/route.ts`, runtime Node.js | ТЗ прямо называет `POST /api/lead`; просто тестировать через HTTP. Server Action не берём |
| БД | PostgreSQL 17: Docker локально, Neon (Vercel Marketplace, free) в проде | Файловая система Vercel эфемерная; один движок везде |
| ORM | Drizzle ORM + drizzle-kit, драйвер `postgres` (postgres.js) | Типизированная схема, SQL-миграции в репозитории, лёгкий рантайм |
| Telegram | Прямой `fetch` к Bot API внутри `after()` из `next/server` | Ответ клиенту не ждёт Telegram |
| Тесты | Vitest, Playwright, @lhci/cli | Раздел 14 |
| Качество кода | ESLint (конфиг Next), Prettier, `tsc --noEmit` | Запускаются хуком и в CI |
| Хостинг и CI | Vercel (Hobby), GitHub Actions | Превью на каждый PR, прод из `main` |

Не берём: UI-киты (shadcn, MUI), framer-motion, react-hook-form, маски ввода, аналитику и любые сторонние скрипты на странице. Форма из 4 полей делается на `useState` + `fetch` без библиотек.

- Все CTA ведут к `#order` и предзаполняют форму: подписка → интерес «Подписка»; «Заказать» у сорта → «Разовый заказ» + комментарий «Эфиопия Иргачеффе, 250 г». Передаём через параметр в хэше или кастомное событие, без глобального стора.

## 5. Форма заявки

Форма должна заполняться одним большим пальцем за 20 секунд: два обязательных поля, выбор интереса кнопками, никаких выпадающих списков.

| Поле | Правила | Атрибуты | Текст ошибки |
| --- | --- | --- | --- |
| Имя | Обязательно, 2–60 символов после trim | `autocomplete="given-name"` | «Напишите, как к вам обращаться» |
| Телефон | Обязательно, мобильный BY: +375 25/29/33/44 + 7 цифр | `type="tel"`, `inputmode="tel"`, `autocomplete="tel"` | «Нужен белорусский мобильный, например +375 29 123-45-67» |
| Что интересует | Одно из: subscription, order, question; по умолчанию subscription | radio-group, визуально чипы ≥ 48 px | – |
| Комментарий | Необязательно, до 500 символов | textarea, 3 строки | «Не больше 500 символов» |
| website (скрытое) | Honeypot: заполнено → сервер тихо отвечает «успех» и ничего не пишет | `tabindex="-1"`, `aria-hidden` | – |

**Номер телефона.** `normalizeByPhone()` убирает пробелы, скобки и дефисы и приводит к `+375XXXXXXXXX`. Принимаем: `+375 29 123-45-67`, `375291234567`, `80291234567`, `8 (029) 123-45-67`, `291234567`. Отклоняем: городские (`+375 17…`), чужие коды стран, лишние или недостающие цифры, буквы. В интерфейсе нет жёсткой маски: только мягкое форматирование на blur, чтобы автозаполнение и вставка работали.

**Когда показываем ошибки.** После ухода из поля (blur) и при отправке, не на каждое нажатие. Текст ошибки под полем, поле связано с ним через `aria-describedby` и `aria-invalid`; при отправке фокус на первое неверное поле. Подсказка про формат номера видна всегда, до ошибки.

**Состояния формы**

| Состояние | Что видит человек | Что происходит |
| --- | --- | --- |
| idle | Форма, кнопка «Оставить заявку» | – |
| submitting | Кнопка «Отправляем…», заблокирована | Один запрос, повторные клики игнорируются; таймаут 10 с |
| success | Форма заменяется карточкой «Спасибо, {имя}! Перезвоним на {номер}» + когда ждать звонка по часам работы | Фокус на заголовок карточки, `aria-live="polite"` |
| duplicate | Та же карточка успеха: «Заявка с этого номера уже у нас – перезвоним» | Не наказываем ошибкой: человек достиг цели |
| validation | Ошибки под полями (в т.ч. пришедшие с сервера) | Данные в полях сохраняются |
| network error | «Не получилось отправить – похоже, пропал интернет. Данные сохранили, нажмите «Повторить»» | Кнопка «Повторить» шлёт тот же idempotency-ключ |
| server error | «У нас что-то сломалось. Попробуйте ещё раз через минуту или напишите нам в Instagram» | Кнопка «Повторить» + ссылка на Instagram |

Имя и телефон дублируем в `sessionStorage` (в try/catch), чтобы при случайной перезагрузке поля не очистились. Под кнопкой – текст из макета «Менеджер перезвонит в рабочее время и всё оформит. Оплата онлайн не нужна.» и строка «Нажимая кнопку, вы соглашаетесь на обработку персональных данных» со ссылкой на `/privacy`, без чекбокса.

**Мелочи, которых нет в макете.** Выбран «Вопрос» → placeholder комментария меняется на «Напишите ваш вопрос» (поле всё равно необязательное). Заявка вне рабочих часов (по времени Минска, Europe/Minsk) → в карточке успеха «Перезвоним завтра после 8:00» (или «после 10:00» в выходные). Ответ 429 → текст из раздела 10.

## 6. API: POST /api/lead

Эндпоинт – Route Handler в том же Next.js-приложении, на Vercel становится serverless-функцией. Отдельный бэкенд не нужен. Сервер не доверяет клиенту и повторяет всю валидацию.

**Запрос** (`Content-Type: application/json`, до 10 КБ):

```json
{
  "name": "Анна",
  "phone": "+375 29 123-45-67",
  "interest": "subscription",
  "comment": "",
  "website": "",
  "idempotencyKey": "8f1c…-uuid",
  "attribution": {
    "utm_source": "instagram", "utm_medium": "paid", "utm_campaign": "autumn_sub",
    "utm_content": "reels_roast", "utm_term": null,
    "click_id": "PAZXh0bgNhZW0…", "click_id_type": "fbclid",
    "referrer": "https://l.instagram.com/",
    "landing_url": "https://kvarta.vercel.app/?utm_source=instagram&…",
    "page_url": "https://kvarta.vercel.app/#order",
    "first_seen_at": "2026-10-16T09:12:00Z"
  }
}
```

**Ответы**

| Код | Тело | Когда |
| --- | --- | --- |
| 201 | `{ ok: true, id, duplicate: false }` | Заявка создана |
| 200 | `{ ok: true, id, duplicate: true }` | Тот же номер за последние 10 минут или тот же idempotencyKey; возвращаем id первой заявки |
| 400 | `{ ok: false, error: "validation", fields: { phone: "…" } }` | Неверные данные; тексты – из общей схемы |
| 413 / 415 | `{ ok: false, error: "bad_request" }` | Слишком большое тело или не JSON |
| 405 | – | Любой метод, кроме POST (Next отдаёт сам) |
| 500 | `{ ok: false, error: "server" }` | БД недоступна и прочее; детали только в лог |
| 403 | { ok: false, error: "forbidden" } | Чужой Origin (раздел 10) |
| 429 | { ok: false, error: "rate\_limited" } | Больше 5 заявок за час с одного IP (раздел 10) |

**Алгоритм**

1. Проверить `Content-Type` и размер, разобрать JSON.
2. Прогнать через zod-схему; номер → `+375XXXXXXXXX`; атрибуцию обрезать до 500 символов на поле.
3. Honeypot заполнен → ответить 201 без записи.
4. В одной транзакции: `pg_advisory_xact_lock(hashtext(phone))` → искать заявку с тем же `idempotency_key` или тем же номером и `created_at > now() - interval '10 minutes'` → нашли: вернуть 200 duplicate; не нашли: INSERT и 201.
5. После ответа, через `after()`: отправить сообщение в Telegram, записать `telegram_status` (`sent` / `failed`). Дубли в Telegram не шлём.

Между шагами 1 и 4 добавляются проверки из раздела 10: чужой `Origin` → 403; honeypot или `startedAt` младше 3 с → тихий 201; больше 5 заявок за час по `ip_hash` → 429.

Почему advisory lock: два параллельных запроса от двойного клика без блокировки оба увидят «дублей нет» и оба вставят строку. Уникальный индекс с окном в 10 минут в Postgres не сделать, а блокировка по номеру сериализует только запросы с одним номером и снимается сама в конце транзакции.

Логи: в лог пишем id и тип исхода, номер – только с маской (`+375 29 ***-**-67`).

## 7. БД и окружения

Один движок – PostgreSQL – во всех окружениях, меняется только `DATABASE_URL`. Файл или SQLite на Vercel не работают: файловая система функций только для чтения, `/tmp` живёт до перезапуска и у каждого инстанса свой – это и есть объяснение для README.

| Окружение | Где БД | Как применяются миграции |
| --- | --- | --- |
| Локально (`pnpm dev`) | `postgres:17` в Docker, база `kvarta` | `pnpm db:migrate` вручную |
| Тесты локально | Тот же контейнер, отдельная база `kvarta_test`, чистится перед каждым тестом | В global setup Vitest |
| CI (GitHub Actions) | Service container `postgres:17` | Шаг в workflow |
| Vercel Preview (PR) | Neon, отдельная ветка БД `preview` (или автоветка на PR, если интеграция это даёт на free) | В скрипте сборки `vercel-build` |
| Vercel Production (`main`) | Neon, ветка `main`, pooled connection string | В скрипте сборки `vercel-build` |

**Vercel + Neon на практике.** Интеграция Neon из Vercel Marketplace сама добавляет `DATABASE_URL` (pooled) и `DATABASE_URL_UNPOOLED`. С включённым Preview branching Neon на каждый превью-деплой создаёт ветку `preview/<git-ветка>`. Миграции – в скрипте `vercel-build` (`pnpm db:migrate && next build`), drizzle-kit ходит по `DATABASE_URL_UNPOOLED`; приложение – по pooled `DATABASE_URL` (advisory lock транзакционный, с PgBouncer совместим). Локальный Postgres в Docker – на порту 5433, чтобы не конфликтовать с другим Postgres на маке. Пошаговая настройка – `docs/SETUP.md`.

**Таблица `leads`**

| Колонка | Тип | Примечание |

| created\_at | timestamptz | `default now()` |
| name | text |  |
| phone | text | E.164 `+375XXXXXXXXX` |
| interest | text + CHECK | subscription / order / question |
| comment | text null |  |
| idempotency\_key | uuid unique null | защита от повторной отправки одной и той же формы |
| utm\_source, utm\_medium, utm\_campaign, utm\_content, utm\_term | text null |  |
| click\_id, click\_id\_type | text null | yclid / fbclid / gclid |
| referrer, landing\_url, page\_url | text null |  |
| first\_seen\_at | timestamptz null | первый заход по рекламе |
| user\_agent | text null | мобильный / десктоп для менеджера |
| telegram\_status | text | pending / sent / failed / skipped |
| ip\_hash | text | SHA-256(IP + соль), только для лимита; индекс (ip\_hash, created\_at) |

Индекс `(phone, created_at desc)` – под проверку дублей.

**Переменные окружения** (в `.env.example` без значений, секреты только в Vercel и GitHub Secrets):

- `DATABASE_URL` – Postgres; для Neon pooled-строка с `sslmode=require`.
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` – не заданы → уведомление пропускается (`skipped`), заявка всё равно сохраняется.
- `NEXT_PUBLIC_SITE_URL` – для metadata и OG.

Плюс `IP_HASH_SALT` – соль для хеша IP (раздел 10). `TELEGRAM_*` задаём только для Production: заявки с превью и тестов не попадают в чат менеджера.

**Скрипты:** `db:up` (docker compose up -d), `db:down`, `db:generate`, `db:migrate`, `db:studio` (Drizzle Studio – чтобы показать заявки без админки). Админку не делаем: заявки менеджер видит в Telegram, полную историю – в Neon Console.

## 8. Атрибуция рекламы

Менеджер в каждой заявке видит три ответа: откуда (источник и кампания), с какого объявления (utm\_content + click id) и с какой страницы (landing\_url и page\_url). Модель – последний рекламный переход.

**Как собираем (`lib/attribution.ts`)**

1. При загрузке страницы читаем из URL `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `yclid`, `fbclid`, `gclid`.
2. Есть хотя бы одна метка → сохраняем набор + `document.referrer` + полный URL входа + время в `localStorage` на 30 дней, перезаписывая старый. Меток нет → ничего не трогаем: человек вернулся по закладке после рекламы.
3. При отправке формы добавляем сохранённое + текущий `page_url`. Нет сохранённого → `utm_source` пустой, в Telegram пишем «прямой заход / {referrer}».
4. Все обращения к `localStorage` в try/catch: во встроенном браузере Instagram и в приватном режиме он может быть недоступен – тогда берём метки прямо из текущего URL.

**Шаблоны ссылок для рекламы** (положить в README)

| Канал | Хвост ссылки | Click id |
| --- | --- | --- |
| Instagram (Meta Ads) | `?utm_source=instagram&utm_medium=paid_social&utm_campaign={{campaign.name}}&utm_content={{ad.name}}` | `fbclid` – добавляется сам |
| Яндекс Директ | `?utm_source=yandex&utm_medium=cpc&utm_campaign={campaign_id}&utm_content={ad_id}&utm_term={keyword}` | `yclid` – добавляется сам |
| Био в Instagram (не реклама) | `?utm_source=instagram&utm_medium=bio` | – |

Сообщение в Telegram показывает атрибуцию человеческим языком: «Источник: instagram / paid\_social · Кампания: autumn\_sub · Объявление: reels\_roast · Страница: /#order».

## 10. Безопасность и персональные данные

Главные риски лендинга с формой – спам и флуд заявками, утечка телефонов и секретов, XSS через данные заявки в Telegram. Закрываем их без капчи и сторонних сервисов: капча режет конверсию и скорость.

| Угроза | Защита | Шаг |
| --- | --- | --- |
| Спам-боты | Honeypot + минимальное время заполнения: форма шлёт `startedAt`, меньше 3 с → тихий 201 без записи | 7–8 |
| Флуд с одного адреса | Не больше 5 заявок в час с одного IP: считаем по `ip_hash` в `leads` → 429 «Слишком много заявок. Попробуйте позже или напишите нам в Instagram» | 7 |
| POST с чужих сайтов | Проверка `Origin`: только свой домен и превью Vercel этого проекта, иначе 403; CORS-заголовки не отдаём | 7 |
| SQL-инъекции | Только Drizzle с параметрами; пользовательские данные никогда не склеиваются в SQL-строку | 7 |
| XSS | React экранирует сам; в Telegram экранируем `< > &`; `dangerouslySetInnerHTML` только для JSON-LD из наших констант | 7, 11 |
| Кривые и большие запросы | До 10 КБ, только JSON, zod `.strict()` (лишние поля → 400), длина каждой строки ограничена, idempotencyKey – только UUID | 6–7 |
| Утечка секретов | Только env; `.env*` в `.gitignore`; GitHub secret scanning + push protection; проверка `ai-log/` перед коммитом; утёк токен бота → отозвать в @BotFather | 1 |
| Утечка деталей ошибок | Клиенту – только код ошибки, стек – в логах Vercel; номер в логах с маской | 7 |
| Уязвимости зависимостей | Последний патч Next.js и React на момент старта, `pnpm audit --prod` в CI, Dependabot | 1–2 |
| Превью-деплои | Vercel Deployment Protection на превью; отдельная ветка БД; Telegram в Preview выключен | 1, 7 |

**Заголовки ответа** (`next.config.ts` → `headers()`, только в production)

```text
Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline';
  img-src 'self' data: blob:; font-src 'self'; connect-src 'self'; object-src 'none';
  base-uri 'self'; form-action 'self'; frame-ancestors 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(), geolocation=()
```

CSP с nonce надёжнее, но делает страницу динамической и ломает статическую сборку. Поэтому берём CSP без nonce (сторонних скриптов на странице нет) и пишем этот компромисс в README. HSTS проверить в ответе прода: Vercel обычно ставит его сам.

**Персональные данные.** Имя и телефон – персональные данные; в Беларуси действует Закон «О защите персональных данных». Для учебного проекта делаем минимум, который показывает понимание темы (это не юридическая консультация):

- Строка согласия под кнопкой со ссылкой на страницу `/privacy`: кто оператор, какие данные и зачем, сколько храним (12 месяцев), как попросить удалить.
- Собираем минимум. IP не храним, только `ip_hash` = SHA-256(IP + соль `IP_HASH_SALT`); user agent обрезаем до 200 символов.
- Telegram-группа с заявками закрытая, в ней только менеджеры и бот.
- Данные в Neon шифруются на стороне провайдера, подключение только по TLS (`sslmode=require`).

**Как проверяем** (добавка к разделу 14): 6-я заявка с одного IP за час → 429; чужой `Origin` → 403; тело > 10 КБ → 413; лишнее поле → 400; `startedAt` младше 3 с → 201 без записи; имя `<b>x</b>` приходит в Telegram экранированным; e2e проверяет заголовки ответа главной. Перед сдачей – проверка на securityheaders.com.

## 12. Git: ветки, коммиты, PR

Упрощённая схема: `main` всегда рабочий и деплоится в прод, каждый шаг – короткая ветка и PR. Ревьюер увидит историю из 10–15 осмысленных PR, а не один коммит.

- Ветки: `feat/…`, `fix/…`, `chore/…`, `test/…`, `docs/…`; живут часы, не дни.
- Коммиты: Conventional Commits на английском (`feat(form): validate BY mobile numbers`), один коммит – одно логическое изменение, которое собирается.
- Слияние: **Rebase and merge** (или merge commit) – не squash, иначе пошаговые коммиты схлопнутся.
- Защита `main`: только через PR, обязательный зелёный CI. Ревью – агент `code-reviewer` + вы.
- Шаблон PR (`.github/pull_request_template.md`): что сделано, как проверить, скриншот мобильной версии, что делал ИИ.
- Vercel: подключён к репозиторию, превью-ссылка в каждом PR, прод – из `main`.
- Репозиторий публичный. Перед первым пушем проверить `.gitignore` (`.env*`, кроме `.env.example`).
